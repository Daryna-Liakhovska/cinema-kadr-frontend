# Кінотеатр «Кадр»: фронтенд

Простий фронтенд для REST API кінотеатру «Кадр». Сторінка показує афішу фільмів з бекенду: можна шукати фільм за назвою або режисером і фільтрувати за жанром. Під афішею є блок «Режисери» зі списком режисерів з `GET /api/v1/directors`. Написано на HTML, CSS і JavaScript без фреймворків. Дані завантажуються через `fetch` з іншого порту, тому бекенд має бути налаштований на CORS.

Бекенд: https://github.com/Daryna-Liakhovska/cinema-kadr

## Сторінки

| Сторінка | Файл | Хто бачить |
|----------|------|------------|
| Афіша: фільми з пошуком і фільтром за жанром, список режисерів | `index.html` | усі |
| Реєстрація | `register.html` | лише неавторизовані |
| Вхід | `login.html` | лише неавторизовані |
| Мій профіль: дані користувача з `GET /api/v1/users/me` | `profile.html` | лише авторизовані |
| Адміністрування в профілі: форма «Додати жанр» | `profile.html` | лише адміністратори |

## Авторизація

- **Реєстрація.** Форма надсилає дані на `POST /api/v1/auth/register`. Якщо дані невалідні, під кожним полем з'являється повідомлення про помилку від сервера. Після успішної реєстрації користувача переносить на сторінку входу.
- **Вхід.** Форма надсилає username і пароль на `POST /api/v1/auth/login`. Отримані access і refresh токени та дані користувача зберігаються в `localStorage` браузера.
- **Запити з токеном.** Усі запити, для яких потрібен вхід, відправляються з заголовком `Authorization: Bearer <access токен>` (функція `apiFetch` у `js/auth.js`).
- **Оновлення токена.** Access токен діє 5 хвилин. Якщо сервер відповідає `401`, фронтенд сам надсилає refresh токен на `POST /api/v1/auth/refresh`, зберігає новий access токен і повторює запит. Користувачеві не потрібно входити знову. Якщо закінчився й refresh токен, токени видаляються, а користувача переносить на сторінку входу.
- **Вихід.** Кнопка «Вийти» видаляє збережені токени з браузера й переносить на афішу.

Поведінка сторінок:

- неавторизованого користувача, який відкриває «Мій профіль», переносить на сторінку входу, а після входу повертає на сторінку, з якої перенаправило (параметр `?next=` в адресі);
- авторизованого користувача, який відкриває сторінку входу чи реєстрації, переносить у профіль;
- неавторизований користувач бачить у шапці посилання «Реєстрація» і кнопку «Увійти»;
- авторизований користувач бачить своє ім'я, посилання «Мій профіль» і кнопку «Вийти».

Уся логіка роботи з токенами зібрана у файлі `js/auth.js`.

## Адреси та порти

| Що | Адреса |
|----|--------|
| Фронтенд | http://localhost:3000 |
| Бекенд (API) | http://127.0.0.1:8000/api/v1 |

Адреса API задана у файлі `js/config.js` (`API_BASE_URL`). Бекенд дозволяє запити з `http://localhost:3000` і `http://127.0.0.1:3000`.

## Як запустити проєкт

1. Запустіть бекенд за інструкцією з його README. Він має працювати на `http://127.0.0.1:8000`.
2. Додайте кілька фільмів через Postman-колекцію бекенду або адмінку Django, щоб сторінці було що показати.
3. У папці цього репозиторію запустіть простий вебсервер на порту 3000:

   ```bash
   python3 -m http.server 3000
   ```

4. Відкрийте в браузері http://localhost:3000.
5. Зареєструйтеся на сторінці «Реєстрація» й увійдіть. Щоб побачити форму адміністрування в профілі, увійдіть як адміністратор (його створює команда `python manage.py createsuperuser` у бекенді).

Відкривати `index.html` подвійним кліком не варто: тоді сторінка відкриється з адресою `file://`, а бекенд дозволяє запити лише з `http://localhost:3000`.
